# PikaView 0.1.1 (formerly OZ Image Viewer)

> **แคนดิเดตที่สร้างขึ้นใหม่จากการกู้คืน — ไม่ใช่รุ่นที่ผ่านการตรวจสอบแล้ว**
> บันทึกฉบับนี้สร้างขึ้นใหม่จากไฟล์ที่กู้คืนได้ เนื่องจากบันทึก v0.1.1 ฉบับเดิมสูญหาย
> แคนดิเดตนี้ยังไม่ผ่านการสร้าง (build) ลงลายเซ็น ทดสอบ ติดตั้ง หรือเผยแพร่
> ข้อความทั้งหมดด้านล่างไม่ถือเป็นการยืนยันว่ามีการสร้างแอป v0.1.1 จริง
> มีลายเซ็นจริง มีผลการทดสอบจริง มีการติดตั้งจริง หรือมีการพิมพ์จริง

PikaView 0.1.1 เป็นแคนดิเดตสืบเนื่องจาก OZ Image Viewer 0.1.0 ภายใต้ชื่อผลิตภัณฑ์
PikaView สำหรับ Windows 64-บิต (x64) ความสามารถด้านการดูภาพ การเลื่อนดูภาพ
การแก้ไขแบบไม่ทำลายต้นฉบับ การบันทึก/ส่งออก และตัวถอดรหัส HEIC/HEIF แบบเลือกได้
ตั้งใจให้ยังคงอยู่ แต่การกู้คืนครั้งนี้ไม่ได้ตรวจสอบความสามารถเหล่านั้นซ้ำ

ชื่อไฟล์โปรแกรมยังคงเป็น `ozviewer.exe` ข้อมูลระบุตัวตนภายในที่ใช้สำหรับการอัปเกรด
และการลงทะเบียนยังคงเดิม ได้แก่ AppId ที่คงที่ ProgID `OZImageViewer.Image`
โครงสร้างรีจิสทรี `HKCU\Software\OZImageViewer` และพาธติดตั้งต่อผู้ใช้
`%LOCALAPPDATA%\Programs\OZ Image Viewer` ส่วนไฟล์และบันทึกเชิงประวัติศาสตร์ v0.1.0
ยังคงไม่ถูกแก้ไขหรือเปลี่ยนเลขรุ่น

## การเปลี่ยนแปลงในแคนดิเดตนี้

- **ชื่อผลิตภัณฑ์ PikaView** ข้อมูลแพ็กเกจและข้อมูลระบุตัวตนสำหรับผู้ใช้เปลี่ยนเป็น
  PikaView (เดิมคือ OZ Image Viewer) โดยชื่อไฟล์โปรแกรมและข้อมูลอัปเกรดภายในยังคงเดิม
  ตามที่ระบุข้างต้น
- **เส้นทางการพิมพ์** คำสั่งพิมพ์แบบโต้ตอบใช้ตัวช่วย `PrintDlgExW` แยกเฉพาะ
  พร้อมวงจรชีวิต COM แบบ apartment-threaded (STA) ที่จำกัดขอบเขตชัดเจน
  จัดการผลลัพธ์ยกเลิก/ใช้งาน/ล้มเหลวอย่างชัดเจน เก็บคืน DevMode/DevNames/HDC ครบถ้วน
  และมีตัวป้องกันการเรียกซ้ำระหว่างพยายามพิมพ์ ส่วนตัวควบคุมการพิมพ์แบบ
  single-flight เดิมจะเตรียมหนึ่งหน้าพอดีพื้นที่จากภาพที่ยืนยันแล้วโดยไม่แก้ไขเอกสาร
- **ไดแอกนอสติกการพิมพ์แบบส่วนตัว** มีตัวเลือก CMake ชื่อ
  `OZVIEWER_PRINT_DIAGNOSTICS` โดยค่าเริ่มต้นเป็น `OFF` และรุ่น Release
  ต้องคงค่าเป็น `OFF` ทั้งนี้ไม่ใช่ฟีเจอร์สำหรับผู้ใช้ทั่วไป
- **แพ็กเกจและ provenance ของรุ่น** สคริปต์แพ็กเกจใช้ชื่อไฟล์ใหม่ด้านล่าง
  และต้องมี `SHA256SUMS` จากไฟล์จริงในขั้นสุดท้าย สคริปต์ provenance
  ผูกไบต์ของ `heif.dll` และ `libde265.dll` ที่จัดเตรียมไว้เข้ากับหลักฐานการสร้าง
  dependency ที่มีผลจริง และจะล้มเหลวแบบปิดเมื่อหลักฐานหายหรือไม่ตรงกัน
  สคริปต์เหล่านี้ถูกกู้คืนมา แต่ยังไม่ได้รันในระหว่างการสร้างใหม่นี้
- **เจตนาการอัปเกรด** ตัวติดตั้งตั้งใจให้อัปเกรดการติดตั้ง v0.1.0 ที่เป็นเจ้าของ
  ในตำแหน่งเดิม และย้ายป้ายชื่อที่ติดตั้งอยู่ในรีจิสทรีเป็น PikaView
  โดยคงโฟลเดอร์ติดตั้งเดิมและไม่เปลี่ยนค่าเริ่มต้นของ Windows โดยอัตโนมัติ
  พฤติกรรมนี้มีเพียงชุดทดสอบสัญญาแบบสังเคราะห์/mock ที่กู้คืนมาเท่านั้น
  ไม่ได้ทำการติดตั้งหรืออัปเกรดจริงในการกู้คืนครั้งนี้

## ไฟล์แพ็กเกจ

- `pikaview-0.1.1-win-x64-installer.exe`
- `pikaview-0.1.1-win-x64-portable.zip`
- `pikaview-0.1.1-lgpl-corresponding-source.zip`
- `SHA256SUMS`

ไฟล์ ZIP แบบพกพายังคงมี `ozviewer.exe` พร้อม DLL สำหรับรันไทม์ที่วางเคียงข้างกัน
ตัวติดตั้งยังคงติดตั้งต่อผู้ใช้ และเสนอการเชื่อมโยงนามสกุลไฟล์เป็นตัวเลือก
ที่ยังไม่ถูกเลือกไว้ก่อน (unchecked) เท่านั้น

บันทึกฉบับที่สร้างใหม่นี้ไม่เผยแพร่ค่า SHA-256 ของ v0.1.1 เนื่องจากยังไม่มีไฟล์จริง
ขั้นสุดท้าย `SHA256SUMS` ต้องสร้างจากไฟล์ที่สร้างจริงในขั้นสุดท้าย
ค่าแฮช v0.1.0 ในบันทึกเชิงประวัติศาสตร์ใช้ได้เฉพาะไฟล์ v0.1.0 ที่เผยแพร่แล้วเท่านั้น
ห้ามนำมาใช้ซ้ำกับ v0.1.1

## สถานะการตรวจสอบและข้อจำกัดของหลักฐาน

- นี่คือ **แคนดิเดตที่สร้างขึ้นใหม่จากการกู้คืน** จากไฟล์ที่รอดชีวิตซึ่งกู้คืนได้
  บนฐาน commit `e299e34` การตรวจสอบระหว่างการสร้างใหม่จำกัดอยู่ที่การแยกวิเคราะห์ JSON
  การตรวจสอบ metadata แบบตรงตัว การตรวจสอบแฮชไฟล์ และการตรวจสอบข้อความ/ซอร์สแบบสถิต
  ที่ไม่ต้องพึ่งงานกู้คืนซอร์สฝั่ง viewer/print ที่ทำพร้อมกัน
- ไม่ได้ทำการ configure/build CMake แบบบูรณาการ ไม่ได้รัน CTest ไม่ได้คอมไพล์ตัวติดตั้ง
  ไม่ได้ตรวจสอบลายเซ็น ไม่ได้รันวงจรติดตั้ง/ถอนการติดตั้ง ไม่ได้พิมพ์จริง
  ไม่ได้ทดสอบกรณีเครื่องพิมพ์เครือข่ายล้มเหลวครั้งแรก และไม่ได้ทำ staging,
  commit, tag, push หรือเผยแพร่ใด ๆ สำหรับแคนดิเดตนี้
- **หลักฐานการพิมพ์เป็นข้อมูลเชิงประวัติศาสตร์เท่านั้น** รายงานความสำเร็จของการพิมพ์หนึ่งหน้า
  และพฤติกรรมการกด Cancel ครั้งที่สองของแคนดิเดตเก่า เป็นข้อสังเกตของแคนดิเดตเก่า
  และสภาพแวดล้อมเดิมเท่านั้น ไม่ใช่หลักฐานของแคนดิเดตนี้
  กรณี failed-network-first (การพยายามพิมพ์ครั้งแรกไปยังเครื่องพิมพ์เครือข่าย
  ที่ล้มเหลวหรือไม่พร้อมใช้งาน) ยังไม่ได้ทดสอบ
  และไม่มีการอ้างว่าอาการค้างของกล่องโต้ตอบพิมพ์ทั้งหมดได้รับการแก้ไขแล้ว
- สคริปต์แพ็กเกจและชุดทดสอบสัญญาแบบสังเคราะห์ที่กู้คืนมาเป็นเพียงไฟล์ที่กู้คืน
  ไม่ใช่หลักฐานรุ่นที่สังเกตได้จริง การเผยแพร่จริงยังต้องมีการสร้างที่สะอาด
  หลักฐาน dependency จริง การตัดสินใจเรื่องการลงลายเซ็นจากไฟล์จริงขั้นสุดท้าย
  และการตรวจสอบอิสระ

## คำเตือนเรื่องไฟล์ที่ไม่ได้ลงลายเซ็น (มีเงื่อนไข)

ยังไม่พบลายเซ็น Authenticode ของไฟล์จริงขั้นสุดท้ายสำหรับแคนดิเดตนี้
**หาก** ตัวติดตั้งหรือไฟล์โปรแกรมขั้นสุดท้ายเผยแพร่โดยไม่ได้ลงลายเซ็น
Windows SmartScreen หรือเบราว์เซอร์อาจแสดงคำเตือน เช่น "Unknown Publisher"
ในกรณีนั้น ให้ตรวจสอบค่า SHA-256 ที่เผยแพร่ใน `SHA256SUMS` และตรวจสอบ
repository อย่างเป็นทางการก่อนรันไฟล์ หากมีการลงลายเซ็นและสังเกตเห็นจริง
ในไฟล์ขั้นสุดท้าย ต้องแทนที่คำเตือนแบบมีเงื่อนไขนี้ด้วยข้อเท็จจริงเรื่องลายเซ็น
และผู้เผยแพร่ที่สังเกตได้ก่อนเผยแพร่
